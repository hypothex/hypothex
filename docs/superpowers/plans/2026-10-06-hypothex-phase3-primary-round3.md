## New findings (blocking)

### P2-D: Task 49's CI job uses the `runner` context in job-level `env`, which makes the whole workflow invalid
- Where: package-acceptance supplement line 228–229 (`env: HX_PACKAGE_ARTIFACTS: ${{ runner.temp }}/hx-package-artifacts` at job level).
- Why: GitHub Actions does not allow the `runner` context in `jobs.<job_id>.env`. Only github, needs, strategy, matrix, vars, secrets and inputs are allowed there. Main uses `runner.temp` only in step-level `env` and `with` (`ci.yml` "Warm the uv cache" step).
- Failure: if this YAML is pasted as written, GitHub rejects `ci.yml` ("Unrecognized named-value: 'runner'"). Then none of the jobs run: not the four test jobs, not ui, not docker, not package. Criterion 9 and every other CI gate turn red. "YAML snippets parse" did not detect this, because the YAML is well-formed and only the expression is invalid.
- Fix: drop the job-level `env`. Set the variable in the steps that need it, for example a step `env: HX_PACKAGE_ARTIFACTS: ${{ runner.temp }}/hx-package-artifacts` on the pytest step, or `"$RUNNER_TEMP/hx-package-artifacts"` in shell. Keep `path: ${{ runner.temp }}/…` in the upload step (`with` allows it). Run actionlint (or one CI push) on the final workflow.

### P2-E: Task 49 step 4.2 says owner discovery "must report `sv/admin`", but planned `hx serve --auth` mints the owner from `$USER`
- Where: supplement line 200 (and "Preserve users" on 201). Backend Task 39 rules at 19227, `owner_name()` at 19455–19475 and `owner = owner_name()` at ~19507. Task 6 `ensure_owner` (2458–2486) inserts that name as a new admin. Task 45 seeds `sv` but does not change serve's owner. The supplement line 156 keeps "ordinary OS runtime variables" and adds only explicit values, and it never sets `USER`.
- Failure: `probes/owner_probe.log` shows that `USER=runner` (GitHub ubuntu) gives local owner `runner`, and `USER=shreyasv` (the user's machine) gives `shreyasv`. So `hx whoami --json` through server.json returns `runner/admin`, and a third admin user appears. The mandatory assertion fails in CI and on the user's machine. The fix needs a choice: pin the env, or change the demo owner semantics. Today the plan does not say which.
- Fix (recommended, smallest): in the team-scenario child env set `USER=sv` explicitly, as the Task 39 tests already do (`env={"USER": "sv"}`). State in the test that local owner discovery is `owner_name()`. Add one line to `docs/package-testing.rst`: `hx serve --auth` adds the OS user as an admin, and the demo's `sv`/`alice` links are the intended browser logins. Other option: assert `whoami.user == owner_name()` under the retained `USER` and that the users set is ⊇ {sv, alice}.

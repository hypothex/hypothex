## Data and claim limits that must remain visible

1. Demo generic macro F1 remains absent; a recorded secondary score is required for the second column and alternate selector option.
2. Demo checkpoint test values remain absent. Checkpoint validation and run-level evaluated best/final test scores are separate populations/artifacts.
3. Legacy score records without evaluator-issued artifact/population bindings do not support cost-normalized claims until a successful reevaluation records the required evidence. Incomplete GPU pricing stays unknown even if a dollar subtotal exists.
4. Demo iteration runs lacking dataset fingerprints correctly show incompatibility. Even with known dataset identity, latest legacy/unbound or aggregate-only evaluations cannot authorize a current waffle; a bound successful reevaluation is required. Browser passing that state is not evidence of a measured waffle; the compatible API-driven path has unit coverage.
5. Missing/incompatible repeat provenance is unavailable, never silently healthy. Sample display is bounded and discloses total/unknown state; comparison outcome discovery is bounded to 100 predictions and names that bound when unsuccessful.
6. Task primary selection updates ranking and supported primary-summary panels. Authored scatter/grid/distribution data definitions are preserved rather than relabelled. Seeds/Repeats affects leaderboard marks only, as the mocks specify.
7. No remaining row is marked deferred except Task export. Earlier worker notes describing group_by toggling, broader primary injection, or browser work as not yet executed are historical snapshots superseded by this source audit and the completed logs above.

Final binding follow-up is implemented and frozen: the UI rejects latest unbound evaluations and requests opt-in `require_bound=true`. The strict server branch validates the current healthy evaluation's exact artifact bytes and full ID/count binding, requires binary outcomes and matching project/task/dataset/source, computes the exact shared intersection of independently complete cohorts, and rechecks files/score/run snapshots before returning. Legacy Examples defaults remain unchanged, and strict UI failures never fall back to them.
